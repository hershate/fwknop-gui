FWKNOP(8)
=========

// 本手册页为 Zurker fork 翻译维护的中文版本，英文原文见同目录的 fwknop.man.en.asciidoc 副本。

名称
----
fwknop - 防火墙敲门操作器（Firewall Knock Operator）


语法
--------
*fwknop* *-A* <'proto/ports'> *-R*|*-a*|*-s -D* <'host'> ['options']

描述
-----------
*fwknop* 实现了一种称为单包授权（Single Packet Authorization，SPA）的授权机制，
用于实现强有力的服务隐藏。SPA 只需要一个经过加密、不可重放、并通过 HMAC
认证的数据包，即可向隐藏在默认丢弃（default-drop）过滤策略防火墙之后的服务
传达所请求的访问权限。SPA 的主要应用是利用防火墙丢弃所有针对 'SSH' 等服务的
连接尝试，从而使漏洞利用（无论是 0-day 还是未打补丁的代码）变得更加困难。
任何被 SPA 隐藏的服务自然无法被 'Nmap' 扫描到。fwknop 项目原生支持四种不同的
防火墙：'iptables'、'firewalld'、'PF' 和 'ipfw'，覆盖 Linux、OpenBSD、
FreeBSD 和 Mac OS X。同时也支持自定义脚本，使 fwknop 能够支持 'ipset' 或
'nftables' 等其他基础设施。

SPA 本质上是下一代的端口敲门（Port Knocking，PK）技术，它在保留 PK 核心
优势的同时解决了 PK 的许多局限性。PK 的局限包括：通常难以防御重放攻击；
通常无法可靠地支持非对称密码和 HMAC 方案；只需在 PK 序列穿越网络时伪造一个
额外的数据包注入其中，就能轻而易举地对 PK 服务器发起 DoS 攻击（从而让 PK
服务器误以为客户端不知道正确的序列）。所有这些局限都被 SPA 解决。与此同时，
SPA 将服务隐藏在默认丢弃的防火墙策略之后，被动地获取 SPA 数据（通常通过
libpcap 或其他方式），并实现用于 SPA 数据包认证和加密/解密的标准密码学
操作。

这是 *fwknop* 客户端的手册页，客户端负责构造 SPA 数据包并将其发送到网络上。
服务器端由 *fwknopd* 守护进程实现，它嗅探网络中的 SPA 数据包并与本地防火墙
交互，以放行经过 SPA 认证的连接。建议同时阅读 'fwknopd(8)' 手册页。更详细的
信息可参阅在线教程 ``Single Packet Authorization: A Comprehensive Guide to
Strong Service Concealment with fwknop''（参见：
'http://www.cipherdyne.org/fwknop/docs/fwknop-tutorial.html'）。

*fwknop* 生成的 SPA 数据包利用 HMAC 以"先加密后认证"（encrypt-then-authenticate）
模型实现认证加密。尽管 HMAC 的使用目前是可选的（通过 *--use-hmac* 命令行开关
启用），但强烈建议使用，原因有三：'1)' 没有 HMAC 时，除非使用 GnuPG，否则
*fwknop* 无法实现密码学强度的认证，但即便如此仍应使用 HMAC；'2)' 在加密之后
应用 HMAC 可以防御针对 CBC 模式的密码分析填充预言攻击（padding oracle），
例如 Vaudenay 攻击及相关的伎俩（如较新的针对 SSL 的 "Lucky 13" 攻击）；
'3)' *fwknopd* 守护进程验证 HMAC 所需的代码比解密 SPA 数据包所需的代码简单
得多，因此没有正确 HMAC 的 SPA 数据包甚至不会被送入解密例程。原因 '3)' 也
解释了为什么即使 SPA 数据包使用 GnuPG 加密仍应使用 HMAC——因为除非 HMAC 首先
校验通过，否则 SPA 数据不会被送入 *libgpgme* 函数处理。GnuPG 和 libgpgme
是相对复杂的代码体，因此通过 HMAC 操作限制潜在攻击者与这些代码交互的能力，
有助于维持更强的安全态势。为 SPA 通信生成 HMAC 需要在常规加密密钥之外使用
一个专用密钥，两者都可以通过 *--key-gen* 选项生成。

*fwknop* 使用 'Rijndael' 分组密码或通过 'GnuPG' 及其相关的非对称密码来加密
SPA 数据包。如果选择对称加密方式，则与通常一样，加密密钥在客户端和服务器
之间共享（详见 *fwknopd* 的 '@sysconfdir@/fwknop/access.conf' 文件）。用于
Rijndael 加密的实际加密密钥通过标准的 PBKDF1 密钥派生算法生成，并使用 CBC
模式。如果选择 GnuPG 方式，则加密密钥来自 GnuPG 密钥环。以客户端身份运行的
fwknop 所生成的 SPA 数据包遵循以下格式（在加密和应用 HMAC 之前）：

..........................
    random data (16 digits)
    username
    timestamp
    software version
    mode (command mode (0) or access mode (1))
    if command mode => command to execute
    else access mode  => IP,proto,port
    message digest (SHA512 / SHA384 / SHA256 / SHA1 / MD5 / SHA3_256 / SHA3_512)
..........................

上述各字段之间以 ":" 字符分隔，因为其中若干字段长度可变，而可能包含 ":"
字符的字段均经过 base64 编码。消息摘要（默认为 *SHA256*）是待加密数据的一
部分，与加密之后附加到 SPA 数据包数据上的 HMAC 相互独立。16 位随机数字
（约 53 比特）确保了任何两个 SPA 数据包都不会相同，这是在 Rijndael CBC
模式下使用 PBKDF1 进行密钥派生（该过程使用一个 8 字节随机"盐"值）之外且
独立于它的额外保障。由于 *fwknopd* 会跟踪所有收到的有效 SPA 数据包的
SHA256 摘要并丢弃重复项，针对 *fwknop* 的重放攻击是不可行的。如果检测到
重放，会生成 syslog 告警。

默认情况下，*fwknop* 客户端通过 UDP 端口 62201 发送授权数据包，但这可以
通过 *--server-port* 参数更改（这要求 *fwknopd* 配置为在所选端口上获取
SPA 数据）。此外，*fwknop* 还可以通过 *--rand-port* 参数经由随机端口发送
SPA 数据包。更多细节参见 'fwknopd(8)'。*fwknop* 客户端的调用示例请参见
*示例* 一节。

*fwknop* 客户端具有很好的可移植性，已知可运行于各种 Linux 发行版（所有
主流发行版以及 OpenWRT 等嵌入式发行版）、FreeBSD、OpenBSD、Mac OS X 以及
Windows 上的 Cygwin。另有一个库 *libfko*，*fwknop* 和 *fwknopd* 都使用它
来进行 SPA 数据包的加密/解密和 HMAC 认证操作。第三方应用程序可以在 GNU
通用公共许可证（GPL v2+）条款下使用该库来使用 SPA。


必需参数
------------------
这些必需参数可以通过命令行指定，也可以在 '~/.fwknoprc' 文件中指定
（参见 '-n, --named-config' 选项以及下文 FWKNOPRC 文件一节）。

*-A, --access*='<port list>'::
    提供一个要访问的端口和协议列表，目标是运行 *fwknopd* 的远程计算机。
    该列表的格式为 ``+<proto>/<port>...<proto>/<port>+''，
    例如 ``tcp/22,udp/53''。*注意：* 绝大多数 *fwknop* 的用法都需要
    *-A* 参数，但通过 *--server-cmd* 参数经由 SPA 数据包发送完整命令给
    *fwknopd* 执行的用法不需要此参数。

*-D, --destination*='<hostname/IP-address>'::
    指示 *fwknop* 客户端向指定目标主机名或 IP 地址上的 *fwknopd*
    守护进程/服务进行认证。连接模式由 *fwknopd* 守护进程/服务在解密并
    解析认证数据包时获知。

*-R|-a|-s*::
    必须使用这三个选项之一（见下文）来告知远程 *fwknopd* 守护进程哪个
    IP 应被放行通过防火墙。建议使用 *-R* 或 *-a* 选项而非 *-s*，以增强
    SPA 通信抵御可能的 '中间人'（Man-In-The-Middle，MITM）攻击的能力，
    并在服务器端的 '@sysconfdir@/fwknop/access.conf' 文件中设置
    'REQUIRE_SOURCE_ADDRESS' 变量。注意，最安全的选项是 *-a*，这样
    *fwknop* 就不必向 'https://www.cipherdyne.org/cgi-bin/myip' 发出
    任何 HTTPS 请求来解析外部可路由 IP 地址。使用 *-a* 要求用户已经
    知道运行 fwknop 的网络的外部 IP。


通用选项
---------------
*-h, --help*::
    打印用法摘要信息并退出。

*-G, --get-key*='<file>'::
    从指定文件加载加密密钥/口令。密钥文件中每个目标主机名或 IP 地址占
    一行，后跟冒号（":"）、可选的空格和口令，最后以换行符结束。注意
    最后一行必须以换行符结尾。另请注意：虽然这种方式很方便，但在系统
    上保存明文口令文件并不是好主意，也不推荐。让 *fwknop* 客户端提示
    您输入密钥通常更安全。还请注意，如果密钥存储在磁盘上，*fwknop*
    的 rc 文件是一种更强大的机制，不仅可以指定密钥，还可以指定其他
    选项。

*--stdin*::
    从标准输入（stdin）读取加密密钥/口令。例如可以用于通过管道传送
    数据。此命令类似于 --fd 0。

*--fd*='<number>'::
    指定用于读取密钥/口令的文件描述符号。如果在用户专属配置节（stanza）
    中未找到口令，且命令行也未提供，此命令可避免提示用户输入口令。
    文件描述符设为 0 时类似于 stdin 命令。

*--get-hmac-key*='<file>'::
    从指定文件加载 HMAC 密钥/口令。与 *--get-key* 选项的格式类似，
    HMAC 密钥文件中每个目标主机名或 IP 地址占一行，后跟冒号（":"）、
    可选的空格和口令，最后以换行符结束。注意最后一行必须以换行符
    结尾。另请注意：虽然这种方式很方便，但在系统上保存明文口令文件
    并不是好主意，也不推荐。让 *fwknop* 客户端提示您输入 HMAC 密钥
    通常更安全。还请注意，如果密钥存储在磁盘上，*fwknop* 的 rc 文件
    是一种更强大的机制，不仅可以指定 HMAC 密钥，还可以指定其他选项。

*--key-gen*::
    让 *fwknop* 生成可用于 SPA 数据包加密和认证的 Rijndael 密钥与 HMAC
    密钥。这些密钥取自 /dev/urandom，经 base64 编码后打印到标准输出，
    应放入 ``$HOME/.fwknoprc'' 文件（或 *--get-key* 所引用的文件）中。
    这类密钥通常比从命令行输入的口令更安全。

*--key-gen-file*='<file>'::
    将生成的密钥写入指定文件。注意如果文件已存在则会被覆盖。如果未
    给出此选项，*--key-gen* 会将密钥写到标准输出。

*--key-len*='<length>'::
    指定生成的 Rijndael 密钥的字节数。目前最大长度为 128 字节。

*--hmac-key-len*='<length>'::
    指定生成的 HMAC 密钥的字节数。目前最大长度为 128 字节。

*-l, --last-cmd*::
    使用上一次调用时的命令行参数（如果有）执行 *fwknop*。上一次的
    参数从 '~/.fwknop.run' 文件中解析出来。

*-n, --named-config*='<stanza name>'::
    指定 ``$HOME/.fwknoprc'' 文件中的配置节（stanza）名称，从中读取
    配置和命令指令。这些命名配置节使用户无需记住频繁使用的 *fwknop*
    调用的各种命令行参数。'.fwknoprc' 文件中有效配置指令的列表请
    参见下文标为 FWKNOPRC 文件 的一节。

*--key-rijndael*='<key>'::
    在命令行上指定 Rijndael 密钥。由于在 Unix 下密钥可能被 'ps' 之类
    的工具看到，这种形式只应在安全性不关键的场合使用。让 *fwknop*
    客户端提示您输入密钥，或通过 ``$HOME/.fwknoprc'' 文件获取，通常
    更安全。

*--key-base64-rijndael*='<key>'::
    指定经 base64 编码的 Rijndael 密钥。由于在 Unix 下密钥可能被
    'ps' 之类的工具看到，这种形式只应在安全性不关键的场合使用。让
    *fwknop* 客户端提示您输入密钥，或通过 ``$HOME/.fwknoprc'' 文件
    获取，通常更安全。

*--key-base64-hmac*='<key>'::
    指定经 base64 编码的 HMAC 密钥。由于在 Unix 下密钥可能被 'ps'
    之类的工具看到，这种形式只应在安全性不关键的场合使用。让
    *fwknop* 客户端提示您输入密钥，或通过 ``$HOME/.fwknoprc'' 文件
    获取，通常更安全。

*--key-hmac*='<key>'::
    指定原始的 HMAC 密钥（未经 base64 编码）。由于在 Unix 下密钥可能
    被 'ps' 之类的工具看到，这种形式只应在安全性不关键的场合使用。
    让 *fwknop* 客户端提示您输入密钥，或通过 ``$HOME/.fwknoprc''
    文件获取，通常更安全。

*--rc-file*='<file>'::
    指定 *fwknop* rc 文件的路径（默认为 ``$HOME/.fwknoprc''）。

*--no-rc-file*::
    执行 *fwknop* 客户端操作时不引用 ``$HOME/.fwknoprc'' 文件。

*--no-home-dir*::
    不允许 *fwknop* 客户端查找与用户关联的主目录。

*--save-rc-stanza*='<stanza name>'::
    将命令行参数保存到 *-n* 选项指定的 ``$HOME/.fwknoprc'' 配置节中。
    如果省略 *-n* 选项，则配置节名称默认为 *-D* 参数给出的目标服务器
    值（主机名或 IP）。

*--force-stanza*::
    与 *--save-rc-stanza* 配合使用，覆盖指定配置节的所有变量。

*--stanza-list*::
    列出 ``$HOME/.fwknoprc'' 中找到的所有配置节。

*--show-last*::
    显示 *fwknop* 上一次使用的命令行参数。

*-E, --save-args-file*='<file>'::
    将命令行参数保存到指定的文件路径。若未使用此选项，且也未指定
    *--no-save-args*，则默认的参数保存路径为 '~/.fwknop.run'。

*--no-save-args*::
    执行 *fwknop* 时不保存所给的命令行参数。

*-T, --test*::
    测试模式。生成 SPA 数据包数据但不发送。而是打印出 SPA 数据各字段
    的分解信息，然后将数据走一遍解密和解码流程并再次打印分解信息。
    这主要是一个调试功能。

*-B, --save-packet*='<file>'::
    指示 *fwknop* 客户端将新生成的 SPA 数据包写入指定文件，以便离线
    检查。

*-b, --save-packet-append*::
    将生成的数据包数据追加到 *-B* 选项指定的文件中。

*--fault-injection-tag*='<tag>'::
    此选项仅在 *fwknop* 编译时支持 libfiu 库的情况下用于故障注入测试
    （参见：'http://blitiri.com.ar/p/libfiu/'）。正常情况下不使用此
    选项，任何打包发行的 fwknop 都不会编入相应代码，因此该能力在
    运行时不启用。此处仅为完整起见加以记录。

*-v, --verbose*::
    以详细模式运行 *fwknop* 客户端。这会让 *fwknop* 打印有关当前命令
    及生成的 SPA 数据的一些额外信息。

*-V, --version*::
    显示版本信息并退出。


SPA 选项
-----------
*--use-hmac*::
    为 SPA 通信的认证加密启用 HMAC 模式。自 *fwknop* 2.5 起这是一个
    可选特性，但在未来的版本中将成为默认行为。

*-a, --allow-ip*='<IP-address>'::
    指定应被允许通过目标 *fwknopd* 服务器防火墙的 IP 地址（此 IP 在
    SPA 数据包内部被加密）。这有助于防止 MITM 攻击——即 SPA 数据包在
    传输途中被截获并从不同于原始来源的 IP 发出。因此，如果 *fwknopd*
    服务器信任 SPA 数据包 IP 头部中的源地址，攻击者就能获得访问权。
    *-a* 选项将源地址放入加密的 SPA 数据包内，从而挫败此类攻击。
    当 SPA 数据包本身通过 *--spoof-src* 选项伪造时，*-a* 选项也可用于
    指定将被授予访问权的 IP。另一个相关选项是 *-R*（见下文），它指示
    *fwknop* 客户端通过查询
    'https://www.cipherdyne.org/cgi-bin/myip' 自动解析本地系统所连接
    到的外部可路由 IP 地址。该服务返回它从调用系统看到的实际 IP 地址。

*-g, --gpg-encryption*::
    对 SPA 数据包使用 GPG 加密（未指定时默认为 Rijndael）。*注意：*
    使用此选项还需要一个 GPG 接收者（参见 *--gpg-recipient* 及下文
    其他与 GPG 相关的选项）。

*--hmac-digest-type*='<digest>'::
    设置用于 SPA 数据包认证加密的 HMAC 摘要算法。可选项有：*MD5*、
    *SHA1*、*SHA256*（默认）、*SHA384*、*SHA512*、*SHA3_256* 和
    *SHA3_512*。

*-N, --nat-access*='<internalIP:forwardPort>'::
    *fwknopd* 服务器能够通过对接 iptables 的 NAT 能力，经由 iptables
    防火墙向内部服务提供 SPA 访问。因此，如果 *fwknopd* 服务器保护的
    是 RFC-1918 地址空间的内部网络，外部的 *fwknop* 客户端可以请求
    服务器将外部端口转发到内部 IP，即 ``+--NAT-access 192.168.10.2,55000+''。
    在这种情况下，将通过端口 55000 向 192.168.10.2 上由 *--access*
    参数所请求的服务（通常是 tcp/22）授予访问权。因此，在发送这样的
    SPA 数据包之后，只需执行 ``ssh -p 55000 user@host''，连接就会被
    自动转发到内部的 192.168.10.2 系统。注意端口 ``55000'' 可以通过
    *--nat-rand-port* 参数（后文介绍）随机生成。

*--nat-local*::
    在 *fwknopd* 服务器上，NAT 操作可以作用于本地系统，而不是经由
    该系统转发。也就是说，对于 iptables 防火墙，到例如 55,000 端口
    的连接可以被转换到本地系统的 22 端口。通过使用 *--nat-local*
    参数，可以让 *fwknop* 客户端请求此类访问。这意味着在 SPA 数据包
    发送之后，任何外部攻击者只会看到经由 55,000 端口的连接，而不是
    预期的 22 端口。

*--nat-port*::
    通常 *fwknop* 用于请求访问运行 *fwknopd* 的系统上的特定端口
    （如 tcp/22）。然而，通过使用 *--nat-port* 参数，可以请求访问某
    个服务（同样以 tcp/22 为例），但经由指定的端口授予访问（此时
    需在 'SSH' 客户端命令行上使用 *-p* 参数）。有关经由 NAT 操作
    访问服务的更多细节，参见 *fwknop* 的 *--nat-local* 和
    *--nat-access* 命令行参数。

*--nat-rand-port*::
    通常 *fwknop* 用于请求访问运行 *fwknopd* 的系统上的特定端口
    （如 tcp/22）。然而，通过使用 *--nat-rand-port* 参数，可以请求
    访问某个特定服务（同样以 tcp/22 为例），但经由一个随机转换端口
    授予访问。也就是说，一旦 *fwknop* 客户端以此模式执行并显示出
    *fwknop* 选定的随机端口，后续客户端使用的目标端口就必须改为与
    该随机端口一致。对于 'SSH'，这通过 *-p* 参数实现。有关经由 NAT
    操作访问服务的更多细节，参见 *fwknop* 的 *--nat-local* 和
    *--nat-access* 命令行参数。

*-p, --server-port*='<port>'::
    指定 *fwknopd* 通过 libpcap 或 ulogd pcap writer 接收数据包的
    端口号。默认情况下 *fwknopd* 在 UDP 端口 62201 上监听授权数据包。

*-P, --server-proto*='<protocol>'::
    设置外发 SPA 数据包使用的协议（udp、tcp、http、udpraw、tcpraw
    或 icmp）。注意：*udpraw*、*tcpraw* 和 *icmp* 模式使用原始套接字
    （raw socket），因此需要 root 权限才能运行。另请注意：*tcp* 模式
    会在发送 SPA 数据包之前先与服务器建立 TCP 连接。通常不会这样做，
    但它有助于与 Tor 兼容以获得强匿名性；参见 'http://tor.eff.org/'。
    在这种情况下，*fwknopd* 服务器需要配置为在目标 TCP 端口（默认为
    62201）上监听。

*-Q, --spoof-src*='<IP>'::
    伪造 *fwknop* 客户端发送 SPA 数据包的源地址。这需要客户端一侧的
    root 权限，因为实现此功能需要原始套接字。注意，在此模式下可以给
    出 *--spoof-user* 参数，以匹配可能在
    '@sysconfdir@/fwknop/access.conf' 中指定的任何 *REQUIRE_USERNAME*
    关键字。

*-r, --rand-port*::
    指示 *fwknop* 客户端通过 10,000 到 65535 之间的随机目标端口发送
    SPA 数据包。*fwknopd* 服务器必须使用配置为接受此类数据包的
    *PCAP_FILTER* 变量。例如，*PCAP_FILTER* 变量可设置为：
    ``+udp dst portrange 10000-65535+''。

*-R, --resolve-ip-https*::
    这是一个重要的选项，它指示 *fwknop* 客户端向运行在
    'cipherdyne.org' 上的一个脚本发出 HTTPS 请求，该脚本返回客户端的
    IP 地址（即 Web 服务器所看到的地址）。在某些情况下，需要用此来
    确定应在远程 *fwknopd* 服务器一侧的防火墙策略中放行的 IP 地址。
    当 *fwknop* 客户端运行于某个位于不明 NAT 地址之后的系统上，且
    用户不知道面向外部互联网的 IP 时，此选项很有用。完整的解析 URL
    为：'https://www.cipherdyne.org/cgi-bin/myip'，*fwknop* 通过
    'wget' 以 *--secure-protocol* 模式访问它。注意，如果用户已经知道
    客户端的外部可路由 IP 地址，使用 *-a* 选项通常更安全，因为这样就
    无需 *fwknop* 发出任何 HTTPS 请求。

*--resolve-url* '<url>'::
    覆盖用于解析源 IP 地址的默认 URL。为获得最佳效果，此处指定的
    URL 应指向一个在 HTTP 响应正文中仅返回 IP 地址的 Web 服务。

*--resolve-http-only*::
    此选项强制 *fwknop* 客户端通过 HTTP 而非 HTTPS 解析外部 IP。
    在某些情况下这可能是必要的，例如 'wget' 不可用（或未编译 SSL
    支持），但通常不推荐这样做，因为它为通过操纵 IP 解析 HTTP
    响应实施的 MITM 攻击打开了可能性。要么用 *-a* 手动指定 IP，
    要么使用 *-R* 并省略此选项。

*-w, --wget-cmd*='<wget full path>'::
    手动设置 'wget' 命令的完整路径。通常 'configure' 脚本会找到
    'wget' 命令，但如果它位于非标准位置，可用此选项指定路径。

*-s, --source-ip*::
    指示 *fwknop* 客户端构造一个包含特殊 IP 地址 ``+0.0.0.0+'' 的
    SPA 数据包，这会告知目标 *fwknopd* SPA 服务器在修改防火墙规则集
    时，使用 SPA 数据包来源的源 IP 地址作为将被放行的 IP。如果
    *fwknop* 客户端部署在 NAT 设备之后且外部 IP 未知，此选项很有用。
    但是，不推荐使用此选项，应改用 *-a* 或 *-R* 选项。放行地址选项
    *-s*、*-R* 和 *-a* 三者互斥。

*-S, --source-port*='<port>'::
    设置外发 SPA 数据包的源端口。

*--server-resolve-ipv4*::
    此选项强制 *fwknop* 客户端在为 SPA 服务器使用主机名时只接受来自
    DNS 的 IPv4 地址。在 DNS 可能同时返回 IPv6 和 IPv4 地址的某些情况
    下这是必要的。

*-f, --fw-timeout*='<seconds>'::
    指定远程防火墙中授予服务访问权的规则保持有效的时长（秒）。
    *fwknopd* 维持的默认值是 30 秒，但在初始放行规则被删除后，任何
    已建立的连接都可以通过防火墙可能提供的连接跟踪机制保持打开。

*-C, --server-cmd*='<command to execute>'::
    *--server-cmd* 参数不是用 SPA 数据包请求访问某个服务，而是指定
    一条将由 *fwknopd* 服务器执行的命令。该命令在 SPA 数据包内被加密，
    并由 *fwknopd* 服务器（照常）从网络上嗅探获得。

*-H, --http-proxy*='<proxy-host>[:port]'::
    指定 *fwknop* 客户端用于发送 SPA 数据包的 HTTP 代理。使用此选项
    会自动将 SPA 数据包传输模式（通常通过 *--server-proto* 参数设置）
    设为 "http"。也可以通过在代理主机名或 IP 后添加 ":<port>" 来
    指定代理端口。

*-m, --digest-type*='<digest>'::
    指定 SPA 数据中使用的消息摘要算法。可选项有：*MD5*、*SHA1*、
    *SHA256*（默认）、*SHA384*、*SHA512*、*SHA3_256* 和 *SHA3_512*。

*-M, --encryption-mode*='<mode>'::
    指定使用 AES 加密 SPA 数据包时的加密模式。默认为 CBC 模式，但
    只要在服务器端 '@sysconfdir@/fwknop/access.conf' 文件中通过
    ENCRYPTION_MODE 变量同样指定，也可以选择 CFB 或 OFB 等其他模式。
    一般来说，建议不要给出此参数，直接使用默认值（CBC）。注意，可以
    指定字符串 ``legacy''，以便按照 2.5 之前版本的 *fwknop* 所使用的
    旧初始化向量策略生成 SPA 数据包。自 2.5 版本起，*fwknop* 通过与
    OpenSSL 兼容的 PBKDF1 算法方式生成初始化向量。

*--time-offset-plus*='<time>'::
    默认情况下，服务器端的 *fwknopd* 守护进程会强制要求客户端与服务
    器系统的时钟保持时间同步。*fwknop* 客户端将本地时间作为时间戳放
    入每个 SPA 数据包中，供 fwknopd 服务器解密后校验。然而在某些情况
    下，如果时钟不同步，而客户端系统上的用户又没有修改本地时钟设置
    所需的权限，就可能难以构造出服务器能接受的时间戳的 SPA 数据包。
    在这种情况下，*--time-offset-plus* 选项允许用户指定一个偏移量
    （例如 ``60sec''、``60min''、``2days'' 等），将其加到本地时间上。

*--time-offset-minus*='<time>'::
    与 *--time-offset-plus* 选项（见上文）类似，但从本地时间戳中减去
    指定的时间偏移量，而不是加上。

*-u, --user-agent*='<user-agent-string>'::
    设置通过 *-R* 解析外部 IP 或通过 HTTP 发送 SPA 数据包时使用的
    HTTP User-Agent。

*--use-wget-user-agent*::
    默认情况下，当 *fwknop* 客户端通过 SSL 使用 *wget* 解析外部 IP
    时，会将 User-Agent 设为 ``Fwknop/<version>''，除非已用上面提到
    的 *--user-agent* 选项手动指定。而 *--user-wget-user-agent* 选项
    则让默认的 *wget* User-Agent 字符串生效，不受 *fwknop* 影响。

*-U, --spoof-user*='<user>'::
    指定包含在 SPA 数据包中的用户名。这使得 *fwknop* 客户端可以满足
    fwknopd 服务器上任何非 root 的 *REQUIRE_USERNAME* 关键字要求
    （*--spoof-src* 模式要求 *fwknop* 客户端以 root 身份执行）。

*--icmp-type*='<type>'::
    在 *-P icmp* 模式下，指定将在 SPA 数据包 ICMP 头部中设置的 ICMP
    type 值。默认为 echo reply。

*--icmp-code*='<code>'::
    在 *-P icmp* 模式下，指定将在 SPA 数据包 ICMP 头部中设置的 ICMP
    code 值。默认为零。


GPG 选项
-----------
注意，将 GPG 用于 SPA 加密/解密可以且应当使用由双方（客户端和服务器）
互相签名的 GPG 密钥。在客户端密钥已传送到服务器、反之亦然之后，基本
流程包含以下步骤：

..........................
    [spaserver]# gpg --import client.asc
    [spaserver]# gpg --edit-key 1234ABCD
    Command> sign

    [spaclient]$ gpg --import server.asc
    [spaclient]$ gpg --edit-key ABCD1234
    Command> sign
..........................

有关此内容的更全面信息可参见：
'http://www.cipherdyne.org/fwknop/docs/gpghowto.html'。

*--gpg-agent*::
    指示 *fwknop* 从正在运行的 gpg-agent 实例（如果可用）获取 GnuPG
    密钥口令。

*--gpg-home-dir*='<dir>'::
    指定 GnuPG 目录的路径；通常该路径取自运行 *fwknop* 客户端的用户
    的主目录（因此默认为 '~/.gnupg'）。当 ``root'' 用户希望登录到
    sshd 守护进程/服务不允许 root 登录的远程机器时，此选项很有用。

*--gpg-recipient*='<key ID or Name>'::
    指定单包授权消息接收者的 GnuPG 密钥 ID，例如 ``+1234ABCD+''（参见
    "gpg--list-keys" 的输出），或密钥名称（关联的电子邮件地址）。此
    密钥由 *fwknopd* 服务器导入，其关联的私钥用于解密 SPA 数据包。
    接收者的密钥必须先导入客户端的 GnuPG 密钥环。

*--gpg-signer-key*='<key ID or Name>'::
    指定签署 SPA 消息时使用的 GnuPG 密钥 ID，例如 ``+ABCD1234+''（参见
    "gpg --list-keys" 的输出），或密钥名称。系统会提示用户输入关联的
    GnuPG 口令以创建签名。这增加了一种密码学强度的机制，使远程服务器
    上的 *fwknopd* 守护进程能够认证 SPA 消息的创建者。

*--gpg-no-signing-pw*::
    指示 *fwknop* 不要为使用 GnuPG 签名密钥获取口令。提供此选项是为
    了便于在自动化环境中进行客户端操作——在这类环境中签名密钥的口令
    已从 GnuPG 密钥环中移除。不过，通常更好的做法是使用 'gpg-agent'
    而不是此选项。

FWKNOPRC 文件
-------------
'.fwknoprc' 文件用于设置各种参数，以便在运行时覆盖程序的默认参数。
它还允许使用额外的命名配置节（'stanzas'），为特定调用设置程序参数。

如果用户主目录中不存在此文件，*fwknop* 客户端会创建它。初始版本包含
一些被注释掉的示例指令。由用户自行编辑此文件以满足其需求。

'.fwknoprc' 文件包含一个默认配置区域（配置节），其中保存覆盖程序默认
值的全局配置指令。您可以编辑此文件并创建额外的'命名配置节'，这些
配置节可用 *-n* 或 *--named-config* 选项指定。命名配置节中定义的参数
将覆盖任何匹配的 'default' 配置节指令。注意，命令行选项仍然会覆盖
任何对应的 '.fwknoprc' 指令。

这些指令与 *fwknop* 支持的大多数命令行参数一一对应。以下是当前各指令
的列表，附带简要说明及其对应的命令行选项：

*SPA_SERVER* '<hostname/IP-address>'::
    指定目标（*fwknopd*）服务器的主机名或 IP
    （'-D, --destination'）。

*ALLOW_IP* '<IP-address>'::
    指定在 SPA 数据中放行的地址。注意：此参数涵盖 *-a*、*-s* 和
    *-R* 命令行选项。可以指定主机名或 IP 地址（*-a* 选项）；指定
    单词 "source"，告知 *fwknopd* 服务器接受数据包的源 IP 作为要放行
    的 IP（*-s* 选项）；或使用单词 "resolve"，让 *fwknop* 通过 HTTP
    请求解析外部网络 IP（*-R* 选项）。

*ACCESS* '<port list>'::
    设置要在防火墙上打开的一个或多个协议/端口（'-A, --access'）。
    该列表的格式为 ``+<proto>/<port>...<proto>/<port>+''，
    例如 ``tcp/22,udp/53''。

*SPA_SERVER_PORT* '<port>'::
    设置发送 SPA 数据包使用的服务器端口（'-p, --server-port'）。

*SPA_SERVER_PROTO* '<protocol'>::
    设置发送 SPA 数据包使用的协议（'-P, --server-proto'）。

*KEY* '<passphrase>'::
    这是用于 SPA 数据包加密的口令，同时适用于 Rijndael 和 GPG 加密
    模式。Rijndael 实际使用的加密密钥由 PBKDF1 算法派生，GPG 密钥
    则取自指定的 GPG 密钥环。

*KEY_BASE64* '<base64 encoded passphrase>'::
    以 base64 编码字符串的形式指定加密口令。这使得 base64 解码后的
    密钥中可以包含非 ASCII 字符。

*USE_HMAC* '<Y/N>'::
    为 SPA 数据包的认证加密启用 HMAC 模式。这会让 *fwknop* 提示用户
    输入一个独立于加密密钥的专用 HMAC 密钥。也可以改用 'HMAC_KEY'
    或 'HMAC_KEY_BASE64' 指令指定 HMAC 密钥（见下文）。

*HMAC_KEY* '<key>'::
    指定用于 SPA 数据包认证加密的 HMAC 密钥。同时支持 Rijndael 和
    GPG 加密模式，并按"先加密后认证"模型应用。

*HMAC_KEY_BASE64* '<base64 encoded key>'::
    以 base64 编码字符串的形式指定 HMAC 密钥。这使得 base64 解码后
    的密钥中可以包含非 ASCII 字符。

*HMAC_DIGEST_TYPE* '<digest algorithm>'::
    设置用于 SPA 数据包认证加密的 HMAC 摘要算法。可选项有：*MD5*、
    *SHA1*、*SHA256*（默认）、*SHA384*、*SHA512*、*SHA3_256* 和
    *SHA3_512*。

*SPA_SOURCE_PORT* '<port>'::
    设置发送 SPA 数据包使用的源端口（'-S, --source-port'）。

*FW_TIMEOUT* '<seconds>'::
    设置防火墙规则的超时值（'-f, --fw-timeout'）。

*RESOLVE_IP_HTTPS* '<Y/N>'::
    设为 'Y' 时自动解析与 *fwknop* 客户端关联的外部可路由 IP。这通过
    'wget' 以 '--secure-protocol' 模式经由 SSL 访问位于
    'https://www.cipherdyne.org/cgi-bin/myip' 的 IP 解析服务完成。

*RESOLVE_HTTP_ONLY* '<Y/N>'::
    当指示 *fwknop* 客户端解析外部客户端 IP 时，此选项设为 'Y' 可
    强制使用 'HTTP' 连接而非 'HTTPS' 连接。当本地操作系统未安装
    'wget'，或 'wget' 未针对 SSL 库编译时，此选项很有用。

*RESOLVE_URL* '<url>'::
    设置用于解析源 IP 地址的 URL（'--resolve-url'）。

*WGET_CMD* '<wget full path>'::
    设置 'wget' 命令的完整路径（用于客户端 IP 解析）。

*TIME_OFFSET* '<time>'::
    设置应用于 SPA 数据包中时间戳的值。可以是正值或负值
    （'--time-offset-plus/minus'）。

*ENCRYPTION_MODE* '<mode>'::
    指定使用 AES 时的加密模式。此变量是 '-M, --encryption-mode' 命令
    行参数的同义词。一般来说，建议不要给出此参数，直接使用默认值
    （CBC）。注意，可以指定字符串 ``legacy''，以便按照 2.5 之前版本
    的 *fwknop* 所使用的旧初始化向量策略生成 SPA 数据包。

*DIGEST_TYPE* '<digest algorithm>'::
    设置 SPA 消息摘要类型（'-m, --digest-type'）。可选项有：*MD5*、
    *SHA1*、*SHA256*（默认）、*SHA384*、*SHA512*、*SHA3_256* 和
    *SHA3_512*。

*USE_GPG* '<Y/N>'::
    设为 'Y' 时指定使用 GPG 进行加密（'--gpg-encryption'）。

*USE_GPG_AGENT* '<Y/N>'::
    设为 'Y' 时让 *fwknop* 与 GPG agent 实例对接以获取 GPG 密钥口令
    （'--gpg-agent'）。Agent 信息本身通过 'GPG_AGENT_INFO' 环境变量
    指定。

*GPG_SIGNING_PW* '<passphrase>'::
    这是在 GPG 加密模式下用于签署 SPA 数据包数据的口令，是 'KEY'
    变量的同义词（即签名口令也可以用 'KEY' 变量指定）。SPA 数据包
    用远程服务器密钥加密，并用本地客户端密钥签名。

*GPG_SIGNING_PW_BASE64* '<base64 encoded passphrase>'::
    以 base64 编码字符串的形式指定 GPG 签名口令。这使得 base64
    解码后的密钥中可以包含非 ASCII 字符。

*GPG_SIGNER* '<key ID or Name>'::
    指定用于签署 GPG 加密的 SPA 数据的 GPG 密钥名称或 ID
    （'--gpg-signer-key'）。

*GPG_RECIPIENT* '<key ID or Name>'::
    指定 GPG 加密的 SPA 数据接收者的 GPG 密钥名称或 ID
    （'--gpg-recipient-key'）。

*GPG_HOMEDIR* '<dir>'::
    指定 GPG 主目录（'--gpg-home-dir'）。默认为 '~/.gnupg'。

*GPG_EXE* '<path>'::
    指定 GPG 的路径（'--gpg-exe'）。默认为 '/usr/bin/gpg'。

*SPOOF_USER* '<user>'::
    将 SPA 数据中的用户名设为指定值（'-U, --spoof-user'）。

*SPOOF_SOURCE_IP* '<IP>'::
    将外发 SPA 数据包的源 IP 设为指定值（'-Q, --spoof-source'）。

*RAND_PORT* '<Y/N>'::
    通过随机分配的端口发送 SPA 数据包（'-r, --rand-port'）。

*KEY_FILE* '<file>'::
    从文件加载加密密钥/口令（'-G, --get-key'）。

*HTTP_USER_AGENT* '<agent string>'::
    设置通过 -R 解析外部 IP 或通过 HTTP 发送 SPA 数据包时使用的
    HTTP User-Agent（'-u, --user-agent'）。

*USE_WGET_USER_AGENT* '<Y/N>'::
    允许在解析外部 IP 时使用默认的 *wget* User-Agent 字符串，而不是
    由 *fwknop* 客户端提供的 User-Agent。

*NAT_ACCESS* '<internalIP:forwardPort>'::
    经由 NAT 访问受 fwknop 服务器保护的内部服务
    （'-N, --nat-access'）。

*NAT_LOCAL* '<Y/N>'::
    经由 fwknopd 服务器系统上转发的端口访问本地服务
    （'--nat-local'）。

*NAT_PORT* '<port>'::
    指定经由 NAT 访问服务时要转发到的端口（'--nat-port'）。

*NAT_RAND_PORT* '<Y/N>'::
    让 fwknop 客户端为 NAT 访问分配随机端口（'--nat-rand-port'）。


环境变量
-----------
*SPOOF_USER*、*GPG_AGENT_INFO*（仅在 *--gpg-agent* 模式下使用）。

SPA 数据包伪装
-------------------
由于 *fwknop* 将要放行通过防火墙的 IP 放在加密的 SPA 载荷之内（除非
使用了 *-s*——不推荐，且可在 *fwknopd* 服务器配置中禁止），SPA 数据包
可以很容易地被伪装，而在此场景下这是件好事。也就是说，SPA 数据包的
源 IP 会被 *fwknopd* 守护进程忽略（当 '@sysconfdir@/fwknop/access.conf'
文件中设置了 'REQUIRE_SOURCE_ADDRESS' 变量时），只有通过认证且被正确
解密的 SPA 数据包中所包含的 IP 才会被授予防火墙访问权。这使得例如
可以伪装成 www.yahoo.com 正在向目标系统进行认证，而实际连接却来自一
个看似毫不相关的 IP。


示例
--------
以下示例说明了在几种情况下可以提供给 fwknop 客户端的命令行参数：

快速上手
~~~~~~~~~~~
使用 *fwknop* 最有效且最简单的方式是让客户端同时生成加密密钥和 HMAC
密钥，然后将它们连同访问请求的具体信息一起保存到 ``$HOME/.fwknoprc''
文件中。这些密钥还需要被传送到运行 *fwknopd* 的系统上。如果有多台
fwknopd 服务器运行在不同系统上，客户端也支持为每个 SPA 目标使用一套
独立的加密密钥和 HMAC 密钥。

因此，假设 IP '2.2.2.2' 是部署了 *fwknopd* 的系统，且该系统上的防火墙
以默认丢弃策略保护着 SSH，那么可以像下面这样运行客户端来生成加密密钥
和 HMAC 密钥：

..........................
    $ fwknop -A tcp/22 --use-hmac -R -D 2.2.2.2 --key-gen --save-rc-stanza --verbose
    [+] Wrote Rijndael and HMAC keys to rc file: /home/user/.fwknoprc
..........................

访问请求参数以及加密密钥和 HMAC 密钥生成并保存到 ``$HOME/.fwknoprc''
之后，密钥本身需要被传送到运行 fwknopd 的 '2.2.2.2' 系统上。一如既往，
应当在启用 SPA、防火墙封锁 SSHD 之前，通过 SSH 等安全手段完成。以下是
'~/.fwknoprc' 文件中新增的 '2.2.2.2' 配置节的样子：

..........................
    $ tail -n 8 /home/user/.fwknoprc
    [2.2.2.2]
    ACCESS                      tcp/22
    SPA_SERVER                  2.2.2.2
    KEY_BASE64                  HvUtIOramehLGKimD4ECXOzinaH4h3U8H1WXum7b54Q=
    HMAC_KEY_BASE64             DLeLf93a3yBT2vhEpM+dWlirGta5GU+jdyG5uXp4461HgOtbqMem4gX0Bp2PJGzYZlbbcavcOM00UPm+0GqkXA==
    USE_HMAC                    Y
    VERBOSE                     Y
    RESOLVE_IP_HTTPS            Y
..........................

这些密钥是随机数据的 base64 编码块，*KEY_BASE64* 和 *HMAC_KEY_BASE64*
两行都应原样复制并放入 '2.2.2.2' 上的
'@sysconfdir@/fwknop/access.conf' 文件中。完成此操作后，即可在该系统
上启动 *fwknopd*，设置针对 SSH 连接的默认丢弃策略，然后通过 fwknop
管理对 SSH 的访问。要访问 SSH，只需使用 *-n* 参数引用 .fwknoprc 文件
中的 '2.2.2.2' 配置节（为便于说明包含了部分 *--verbose* 输出）：

..........................
    $ fwknop -n 2.2.2.2

    FKO Field Values:
    =================

       Random Value: 8950423288486978
           Username: mbr
          Timestamp: 1370194770
        FKO Version: 2.5
       Message Type: 1 (Access msg)
     Message String: 1.1.1.1,tcp/22
         Nat Access: <NULL>
        Server Auth: <NULL>
     Client Timeout: 0 (seconds)
        Digest Type: 3 (SHA256)
          HMAC Type: 3 (SHA256)
    Encryption Type: 1 (Rijndael)
    Encryption Mode: 2 (CBC)
    ...

    $ ssh -l user 2.2.2.2
    user@2.2.2.2's password:
..........................

访问模式示例
~~~~~~~~~~~~~~~~~~~~
*fwknop* 最常见的用法是获取对远程系统上 SSH 的访问权，该远程系统部署了
*fwknopd* 守护进程和默认丢弃的防火墙策略。以下命令演示了这种用法，其中
IP '1.1.1.1' 是将被允许通过运行于 '3.3.3.3' 上的防火墙的 IP（注意，
*fwknopd* 读取的 '@sysconfdir@/fwknop/access.conf' 文件中需要有匹配的
加密密钥和 HMAC 密钥，配置细节可参见 'fwknopd(8)' 手册页）。另请注意，
下面的示例通过 stdin 提示用户提供加密密钥和 HMAC 密钥，而不是像上面的
示例那样使用 ``$HOME/.fwknoprc'' 文件将它们写入磁盘。不过，以下所有
示例只需添加 *--save-rc-stanza* 参数即可转换为使用 ~/.fwknoprc 文件的
方式：

..........................
    $ fwknop -A tcp/22 --use-hmac -a 1.1.1.1 -D 3.3.3.3
    Enter encryption key:
    Enter HMAC key:
    $ ssh -l user 3.3.3.3
    user@3.3.3.3's password:
..........................

如果在命令行中加上 *--verbose* 标志，则会向标准输出打印一些 SPA 数据包
的具体信息（为简洁起见未显示全部输出）：

..........................
    $ fwknop -A tcp/22 --use-hmac -a 1.1.1.1 -D 3.3.3.3 --verbose
    Enter encryption key:
    Enter HMAC key:

       Random Value: 1916307060193417
           Username: mbr
          Timestamp: 1368498909
        FKO Version: 2.5
       Message Type: 1 (Access msg)
     Message String: 1.1.1.1,tcp/22
         Nat Access: <NULL>
        Server Auth: <NULL>
     Client Timeout: 0 (seconds)
        Digest Type: 3 (SHA256)
          HMAC Type: 3 (SHA256)
    Encryption Type: 1 (Rijndael)
    Encryption Mode: 2 (CBC)
..........................

也支持同时访问多个服务，以下示例请求访问 '3.3.3.3' 上的 'SSH' 和
'OpenVPN'：

..........................
    $ fwknop -A "tcp/22,tcp/1194" --use-hmac -a 1.1.1.1 -D 3.3.3.3
..........................

许多情况下，*fwknop* 客户端部署在 NAT 设备之后的网络中，用户不知道
外部可路由 IP。此时可通过 *-R* 命令行开关使用位于
'https://www.cipherdyne.org/cgi-bin/myip' 的 IP 解析服务来获取外部
客户端 IP 地址。这比使用本手册页前文提到的 *-s* 选项更安全，因为
源 IP 被放入加密数据包之内，而不是由 *fwknopd* 守护进程直接放行
SPA 数据包来源的任何 IP 地址（即使用 *-s* 存在遭受 MITM 攻击的
可能性）：

..........................
    $ fwknop -A tcp/22 --use-hmac -R -D 3.3.3.3
..........................

使用单包授权模式获取对 'SSH' 的访问权，这次使用 GnuPG 密钥进行加密
和解密：

..........................
    $ fwknop -A tcp/22 --use-hmac --gpg-sign ABCD1234 --gpg--recipient 1234ABCD -R -D 3.3.3.3
..........................

指示运行在 3.3.3.3 上的 fwknop 服务器允许 1.1.1.1 连接到 'SSH'，但
将授权数据包伪装成来自与 'www.yahoo.com' 关联的 IP（在 *fwknop* 客户端
操作系统上需要 root 权限）：

..........................
    # fwknop --spoof-src "www.yahoo.com" -A tcp/22 --use-hmac -a 1.1.1.1 -D 3.3.3.3
..........................

当 *fwknopd* 运行在 iptables 防火墙上且其后方部署有系统时，可以利用
iptables 提供的 NAT 能力，通过 SPA 透明地访问防火墙后方的系统。以下
示例中，*fwknop* 客户端用于访问运行在 '3.3.3.3' 后方网络上不可路由
IP '192.168.10.23' 上的 SSH。在这种情况下，对 '3.3.3.3' 发起的 SSH
连接会被自动经 NAT 转换到 '192.168.10.2' 系统：

..........................
    $ fwknop -A tcp/22 -N 192.168.10.2:22 -R -D 3.3.3.3
..........................


向后兼容性
-----------------------
在 '2.5' 版本中，*fwknop* 在密码学使用方面发生了重大变化，包括为
Rijndael 和 GnuPG 两种模式增加了 HMAC 认证加密支持，确保 Rijndael 加密
SPA 数据包时正确使用 PBKDF1 进行密钥派生，并修复了 fwknop 早期版本中的
若干缺陷。总体而言，这意味着在使用 Rijndael 时，'2.5' 版本生成的 SPA
数据包与 fwknop 早期版本不兼容。GnuPG 加密模式不受这些更新影响。不过，
即使使用 Rijndael，也可以通过在 fwknop 客户端命令行上用 *-M* 和/或在
'@sysconfdir@/fwknop/access.conf' 文件中用 'ENCRYPTION_MODE' 变量设置
'legacy' 加密模式来支持向后兼容。这样，2.5 之前的服务器可以解密 2.5
及以后版本的客户端生成的 SPA 数据包（设置 '-M legacy'），2.5 及以后
版本的服务器也可以解密 2.5 之前客户端生成的 SPA 数据包（在 access.conf
文件中设置 'ENCRYPTION_MODE legacy'）。注意，HMAC 仅从 2.5 起才受支持
且为可选特性，因此向后兼容仅适用于两端都不使用 HMAC 的配置。强烈建议
将所有 fwknop 客户端和服务器升级到 2.5，并使用新的 HMAC 模式以获得
正确认证的 SPA 通信。向后兼容支持用于使客户端和服务器的分阶段升级更
加容易。

特别强调，如果 *fwknopd* 服务器已升级到 2.5（或更高版本），但旧客户端
无法同时升级，则需在 '@sysconfdir@/fwknop/access.conf' 文件中的每个
'SOURCE' 配置节中添加以下一行：

..........................
    ENCRYPTION_MODE         legacy
..........................

此外，如果 'KEY' 变量的加密密钥长于 16 字节，则需要在 'access.conf'
文件中将其截断为 16 个字符，2.5 之前的客户端才能正常工作。此限制已在
2.5 中修复，这也为将所有客户端和服务器升级到 2.5 或更高版本提供了
额外的动力。

现在，把场景反过来：如果 *fwknop* 客户端已升级，而 *fwknopd* 服务器
仍是 2.5 之前的版本，则在 fwknop 命令行中添加 '-M legacy' 参数：

..........................
    $ fwknop -A tcp/22 -M legacy -R -D 2.2.2.2
..........................


依赖
------------
*fwknop* 客户端需要 'libfko'，它通常随源代码和二进制发行版一同提供，
是 fwknop 项目开发的专用库。只要使用 *fwknopd* 服务器，'libpcap' 就是
必需的依赖。不过，即将发布的 '2.6' 版本将提供 UDP 监听模式和特权分离
支持，在此模式下不需要 libpcap。在 UDP 监听模式下，尽管 fwknopd 绑定
到一个 UDP 端口，SPA 数据包也永远不会被应答，因此从攻击者的角度看，
就可扫描性而言，fwknopd 被动嗅探网络与监听 UDP 套接字没有任何区别。

GPG 功能还要求正确安装和配置 GnuPG 以及 'libgpgme' 库。

要利用 *fwknopd* 守护进程/服务的全部认证和访问管理功能，底层操作系统
上需要一个正常工作的 'iptables'、'ipfw' 或 'pf' 防火墙。


诊断
-----------
获取 *fwknop* 诊断信息最全面的方式是运行位于 fwknop 源代码 'test/'
目录中的测试套件脚本 'test-fwknop.pl'。该测试套件让 fwknop 经历大量
运行时测试，支持 'valgrind'，针对 OpenSSL 校验 SPA 加密和 HMAC 结果，
甚至还内置了自己的 SPA 通信模糊测试器（fwknop 2.6.4 版本还支持 Michal
Zalewski 的 'American Fuzzy Lop'（AFL））。如需更基础的诊断信息，可以
使用 *-T*（或 *--test*）命令行选项执行 *fwknop*。这会让 *fwknop* 只是
创建并打印 SPA 数据包信息，然后将其走一遍解密/解码流程并再次打印。
此外，*--verbose* 命令行开关也有助于查看打印到标准输出的各种 SPA
数据包具体信息。


本 fork（Zurker）新增功能
--------------------------
以下为本 fork 在上游 2.6.11 基础上新增的客户端能力（对应 SPA 协议
4.0.0；英文原版手册无此节）。

*新增命令行选项：*

*--totp-port*::
    将 SPA 包发往由当前 TOTP 值推导出的目的端口（端口跳变 SPA）。
    需要配合 *--totp-seed* 使用。

*--totp-seed*='<base64 种子>'::
    用于计算跳变目的端口的 base64 编码 TOTP 种子（RFC 6238，
    HMAC-SHA256，30 秒步长）。

*--port-range*='<START-END>'::
    *--totp-port* 的目的端口范围（默认 30000-60000）。

*--device-id*='<设备标识>'::
    设置 SPA v4 数据包中作为可选末字段携带的设备身份（如设备指纹）。
    旧版（v3）数据包不含此字段，服务端向后兼容。

*对应的 rc 文件指令：* 'USE_TOTP_PORT'、'TOTP_SEED_BASE64'、
'PORT_RANGE'、'DEVICE_ID'，可写入 ``$HOME/.fwknoprc'' 的 stanza 中，
与命令行选项一一对应。

*易用性子命令：*

*fwknop setup*::
    交互式配置向导：生成 Rijndael/HMAC 密钥、TOTP 种子与设备指纹，
    并输出服务端 access.conf stanza 与客户端 rc stanza。

*fwknop knock* '<配置名>'::
    等价于 'fwknop -n <配置名> -R'：按命名配置直接发起敲门。

*fwknop lint* '[rc 文件]'::
    检查 rc 文件各 stanza 的一致性（缺密钥、设置了 USE_HMAC 但无
    HMAC 密钥、设置了 USE_TOTP_PORT 但缺 TOTP 种子或端口范围等）。

*fwknop import* '<fwknop://uri | cred.json | qr.png>' '[--rc-file F]'
'[--passphrase P]'::
    把 fwknopd-admin 签发的授权凭证（fwknop:// URI、加密的凭证 JSON
    文件或 QR 图片）解密并导入为本地 rc stanza。

*fwknop profile list* '[--rc-file F]'::
    列出 rc 文件中的全部命名配置（profile）。
