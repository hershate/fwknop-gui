# 02 · 架构与代码结构

## 1. 三大组件

| 组件 | 目录 | 产物 | 职责 |
| --- | --- | --- | --- |
| **libfko** | [lib/](../lib/) | `libfko.la` / `libfko.so` / `libfko.lib` | SPA 全部密码学：编码/加密/解码/HMAC/重放摘要 + 本 fork 新增的 TOTP/device_id/指纹 |

## 3. SPA 数据格式（编码明文）

冒号分隔，由 [lib/fko_encode.c](../lib/fko_encode.c) 的 `fko_encode_spa_data` 拼装：

```
<rand 16位>:<b64(username)>:<timestamp>:<version>:<message_type>:<b64(message)>
[:b64(nat_access)][:b64(server_auth)][:client_timeout][:b64(device_id)]
```

- v3（上游）：前 9 个字段。
- **v4（本 fork）**：在末尾新增可选第 10 字段 `device_id`（base64）。详见 [03-二次开发增强方案.md](03-二次开发增强方案.md#2-spa-v4-device_id字段)。
- `message` 格式（[lib/fko_message.c](../lib/fko_message.c)）：访问型 `<IP>,<proto>/<port>`、命令型 `<IP>,<cmd>`、NAT 型 `<host>,<port>`。

之后追加 `digest`（SHA-256 等），整体加密后再追加 `HMAC`。

## 4. 加密流水线（encrypt-then-MAC）

[lib/fko_funcs.c](../lib/fko_funcs.c) 的 `fko_spa_data_final`：

1. 拼装编码明文 → 追加摘要（默认 SHA-256）。
2. Rijndael/AES-CBC 加密（密钥经 OpenSSL 兼容 salt+IV+MD5 派生，[lib/cipher_funcs.c](../lib/cipher_funcs.c)），或 GnuPG。
3. base64，去 `Salted__` 前缀。
4. **先加密后认证**：追加 HMAC（强烈推荐 `--use-hmac`）。

encrypt-then-MAC 顺序可抵御 CBC 填充预言攻击（Vaudenay / Lucky 13），且让服务端先验 HMAC 再解密，缩小攻击面。

## 5. 服务端验证管线

[server/incoming_spa.c](../server/incoming_spa.c) 的 `incoming_spa`，关键顺序（任何扩展都必须插入到正确阶段）：

1. `preprocess_spa_data`：base64 合法性（可选 SPA-over-HTTP 解包）。
2. `src_check`：源 IP 是否被某 stanza 的 `SOURCE` 覆盖；命中则计算**外层 raw digest**（无密钥）做 `is_replay` 重放检查——**在解密之前**。
3. 遍历 `acc_stanzas`：`fko_new_with_data` 一次性完成 **HMAC 验证 + 解密**；成功后 `add_replay_cache`。
4. `check_pkt_age`（`ENABLE_SPA_PACKET_AGING` + `max_spa_packet_age`）校验新鲜度。
5. 拆 `spa_message`、校验嵌入 IP / `REQUIRE_USERNAME` / NAT 权限 / 端口策略（`acc_check_port_access`）。
6. 动作派发：`CMD_CYCLE_OPEN` / `process_cmd_msg` / `process_spa_request`（开端口）。

> 阶段 4（待办）的「指纹白名单 + 可选 TOTP 端口匹配」将插入在第 4–5 步之间。

## 6. 抓包后端（编译期选择，优先级 NFQ > UDP > pcap）

- [server/pcap_capture.c](../server/pcap_capture.c)：libpcap，BPF 默认 `udp port 62201`。
- [server/udp_server.c](../server/udp_server.c)：UDP socket 绑定 `INADDR_ANY:62201`，无 libpcap 依赖。
- [server/nfq_capture.c](../server/nfq_capture.c)：Netfilter Queue，匹配 `NFQUEUE` 规则投递，投递后 DROP。**端口范围监听的最佳载体**（阶段 2 目标）。

## 7. 防火墙后端（编译期选一）

iptables（参考实现，[server/fw_util_iptables.c](../server/fw_util_iptables.c)）：自定义链 `FWKNOP_INPUT` 等，从 `INPUT` 跳入；
规则形如 `-A FWKNOP_INPUT -p tcp -s <ip> --dport 22 -m comment --comment _exp_<过期时间戳> -j ACCEPT`；
`check_firewall_rules` 周期扫描注释里的 `_exp_` 并 `-D` 过期规则。另有 firewalld / pf(anchor) / ipfw / ipf。

## 8. 客户端配置（~/.fwknoprc）

[client/config_init.c](../client/config_init.c) 两趟解析：CLI（`getopt_long`，[client/cmd_opts.h](../client/cmd_opts.h)）+ `~/.fwknoprc` 的 `[stanza]`，命令行优先级最高。
`--key-gen`（[lib/fko_funcs.c](../lib/fko_funcs.c) `fko_key_gen`）生成 Rijndael + HMAC 密钥。本 fork 在此基础上新增 `USE_TOTP_PORT` / `TOTP_SEED_BASE64` / `PORT_RANGE` / `DEVICE_ID` 等变量。
