# dashboard 网络暴露面安全与稳定性审计（2026-09-05）

> 背景：面板以 0.0.0.0 暴露于 LAN，需在「不信任任何客户端输入」的前提下
> 长期高负载稳定运行。五轮审计各自覆盖不同方面；每轮修复均经实测验证后
> 细粒度提交。本报告为总账，逐轮细节见各 commit。

## 结论

审计发现的全部实质缺陷共 **3 类 9 项**，已全部修复并机器验证；
掩码/门禁等既有红线经测试固化为回归资产。当前代码在认证、输入校验、
并发落盘、资源边界四个层面闭环。

## 各轮覆盖与结果

| 轮 | 方面 | 发现与处置 |
| --- | --- | --- |
| 1 | 认证与会话、HTTP 入口 | **修复**：服务器无整体超时（慢速体/空闲连接占资源）→ 补 Read/Write/Idle 超时矩阵；请求体无上限（未认证大 JSON 驱动无界分配）→ 全局 8MB + 认证端点 64KB；setup 初始化 TOCTOU（并发双写覆盖）→ CAS 门闩；logout 缺 CSRF 校验 → 补齐。实测：1MB 登录体被拒/401 限流不变/无头注销 403 |
| 2 | 零信任输入与命令执行面 | **修复**：fwknopd-admin 把 name/user/server 等值原样 printf 进 stanza 文本，值内换行可走私指令行进 access.conf（预检只验语法不验来源）→ valueFieldOK 统一护栏（禁控制字符/非 UTF-8/超长；数字字段精确形状；位置参数拒前导 '-'）。实测：恶意换行名 400、正常中文名 200。核查项：runAdmin 无 shell 注入面（手写 strcmp 解析，无 getopt 重排）；tar 导入 Base 白名单防 zip-slip；备份名/方案名锚定正则防穿越 |
| 3 | 并发与数据完整性 | **修复**：全部配置写路径 tmp 文件名仅含 PID，同进程并发请求互踩，最坏交错使未校验内容被他人 rename 提升落盘（绕过预检门禁）→ confWriteMu 串行化 10 个写入口 + tmp 名追加纳秒。验证：`-race` 构建下 16 并发 × 7 混合读写 112 请求全成、0 数据竞争、终态一致 |
| 4 | 资源与长跑稳定性 | **验证通过（无缺陷）**：exec 全部 CommandContext 带超时；文件句柄 defer Close；tailBytes/journalctl 2MB 封顶；审计下载流式 io.Copy；方案导出内存有界；sessions/failures/审计尾缓存/R3 解析缓存均有淘汰或上限；guard() 覆盖除认证四端点外全部路由（逐一核对 38 条注册） |
| 5 | 前后端契约与安全不变量 | **验证通过 + 固化**：前端全部 API 调用与后端路由一致（profiles 子动作走前缀路由分发、下载走 `<a href>`）；新增 masking_test.go 把「密钥材料零泄露」固化为回归测试（逐指令含冒号变体 + 备份预览端到端） |

## 既有红线确认（未改动，测试守护）

- HMAC 先于解密、时序安全比较（subtle.ConstantTimeCompare）——lib 层，未触碰
- 密钥只由 fwknopd-admin 产出，面板自身永不读取原文——掩码测试守护
- 登录限流（5 次/5 分钟/锁 60s）与会话 12h TTL——实测未回归
- CSRF：全部写端点要求 X-Fwknop-Request（含本轮补齐的 logout）

## 遗留观察（记录不处置）

- 登录限流按客户端 IP 计：NAT 后多用户共享锁定（既有权衡，注释已说明）
- 首次初始化先到先得：0.0.0.0 暴露时建议首次部署即完成初始化，或绑回
  localhost/走 SSH 隧道（README 安全模型如此建议）
