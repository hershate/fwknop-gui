# 事件轮询增量拉取（2026-08-23，commit f81a642f）

## 改动

- 服务端：`GET /api/events` 新增 `?since=<epoch>` 参数，只返回该时刻（含）
  之后的事件；空结果保证输出 `[]` 而非 `null`。
- 前端：`loadEvents()` 以本地已知最新事件时刻为 `since` 轮询，按全字段
  复合键（time|event|user|src_ip|device_id|spa_port|target_port|stanza|reason）
  去重合并，封顶 500 条（与服务端缓存一致）。
- 面板内「清理审计日志」动作同步重置本地事件缓存与水位（否则 since 悬空，
  清空后旧事件永不被替换）。

## 收益估算

- 改动前：每次自动刷新（默认 5 秒）全量传输最近 500 条审计事件
  （每条 JSON 约 150-250 字节，满载约 75-125 KB/次）。
- 改动后：稳态（无新事件）每次仅返回 `[]`（2 字节 + 头）；有事件时只传
  增量条数。边界秒事件可能重发，前端去重吸收。
- 长期挂着的监控页（面板典型用法）网络传输量下降约 99%（稳态）。

## 验证

- fork 回归新增 2 用例：since=未来时刻返回空数组；since=1 返回全量。
  套件 106 → 108 PASS。
- 同秒多事件去重依赖复合键含全部审计字段，除同秒同用户同端口同原因的
  完全重复包（语义上本就可合并）外无误杀。
