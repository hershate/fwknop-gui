# R7 — 性能专项收敛评估（2026-09-05）

> 临时剖析夹具（不入库）实测数据 + 剩余候选项的否决理由。本报告是
> 性能循环（R0~R6）的收官决策记录。

## 终态剖析（阶段法，-O2，同机同日）

| 路径 | 实测 | 判读 |
| --- | ---: | --- |
| fko_new + fko_destroy | 14.2 µs | 一次性上下文构建（calloc 树 + 随机值 + 字段初始化），每包一次 |
| client_full_packet（完整产包） | **18.2 µs** | ≈5.5 万包/秒/核；扣除 new 后编码+加密+HMAC 仅 ~4µs（R1/R2 成果） |
| server_verify_full（验包） | ~13 µs | HMAC 先行 + AES + 解码 + 摘要，纯密码学下界 |
| 面板全部日志类读取（热路径） | µs 级 | R3/R5/R6 缓存覆盖 |
| 面板日志类读取（冷路径） | 恒定 ~17ms | R6 窗口化，与日志体积解耦 |
| 页面首载 / 复访 | 208KB / 304 | R4 预压缩 + 强 ETag |

## 剩余候选项否决理由（红线约束下）

| 候选 | 预期收益 | 否决理由 |
| --- | --- | --- |
| fko_new 上下文池化复用 | ~14µs/包 | 客户端敲门每包仅一次（一次性动作），用户零感知；池化引入生命周期/清零语义风险，违背"安全红线优先" |
| Rijndael T-table 重写/指令级优化 | AES ~2-3× | AES 在验包路径仅占 ~12µs 的一部分；重写密码核 = 引入侧信道风险的高危操作，收益/风险比极差 |
| 内嵌 JS 压缩（去注释/空白） | gzip 后再省 ~30% | 7873 行内联 JS 无构建管线，文本级压缩器需完整 JS 词法（字符串/正则/模板区分），一处误判即整页瘫痪；LAN 场景 208KB 体感无差 |
| API 响应 gzip | <10KB 体 | 无感知收益，徒增 CPU |
| pcap 循环调参 | 网络面 | 上游成熟代码，参数已按负载调优 |

## 结论

R0~R7 六轮优化 + 一轮评估收官：**C 数据面 3.4×（产包）/2.5×（验包），
面板全部轮询与日志路径缓存化（17×~132×），传输层 3×+304 复用**。
所有高价值面已覆盖；剩余项在安全性/稳定性红线下收益为负。
后续如出现具体性能体感问题，按单点剖析处理，不再 blanket 轮询。
