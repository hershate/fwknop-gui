# 2.4.1 版本（2026-08-23）—— WebUI 默认管理模式

## 背景与目标

面板此前默认只读，管理写操作需显式加 `-enable-write`。作为管理工具，默认
只读反而增加使用摩擦；鉴权体系（2.4.0：初始化 + 登录 + 限流 + CSRF）已经
就位后，默认值翻转为管理模式更合理。只读成为显式选项。

## 改动明细

### 后端（server/dashboard）

- **main.go**：`-enable-write` 默认值改为 `true`（保留该参数仅为兼容旧启动
  脚本）；新增 `-read-only` 布尔开关，设置后强制 `EnableWrite=false`。
  版本号 2.4.1。
- **api.go**：`requireWrite` 拒绝文案改为「当前为只读模式（去掉 -read-only
  重启以启用写操作）」。

### 前端（web/index.html）

- 版本标识 v2.4.1；关于页安全说明改为「写操作默认即为管理模式；如需只读
  展示，启动时加 `-read-only`」。
- 只读提示、403 toast、概览「写操作模式」卡片、方案空状态文案同步更新。

### 测试（test/run_fork_tests.sh）

- 鉴权第二实例（18098）刻意不再传 `-enable-write`，「带 CSRF 头的写操作
  成功」用例同时验证默认管理模式。
- 新增第三实例（18097，`-read-only` + Bearer）三个用例：auth/state 报告
  `write_enabled:false`；写操作 403 且提示只读模式；读接口正常。
- 全套回归 **79 通过 / 0 失败**。

## 兼容性说明

- 行为变更：此前不加 `-enable-write` 的部署升级后将处于管理模式（仍受
  登录 + CSRF 防护）。需要只读语义的部署请显式加 `-read-only`。
- 旧脚本中的 `-enable-write` 继续有效（等价于默认行为）。
