# 2.4.0 版本（2026-08-23）—— WebUI 首次启动初始化与强制鉴权

## 背景与目标

运维面板此前仅依赖可选的 `DASHBOARD_TOKEN` 保护写端点：不设令牌时任何能访问
端口的人都能直接读状态、甚至（在 `-enable-write` 下）管理 fwknopd。作为对外
提供网络服务的管理入口，这是不可接受的。2.4.0 将面板升级为**强制鉴权**模型：
第一次启动必须走初始化流程（设置管理员密码），之后凭登录会话使用。

## 改动明细

### 后端（server/dashboard）

- **新增 auth.go**：
  - 首次启动初始化 `POST /api/setup`：未初始化（无认证文件且未设
    `DASHBOARD_TOKEN`）时才可用；密码至少 8 位且两次输入一致；成功即自动登录。
    已初始化后返回 409。
  - 密码存储：PBKDF2-HMAC-SHA256（10 万轮、16 字节随机盐、32 字节输出），
    JSON 写入 `<run-dir>/dashboard_auth.json`（0600，tmp+rename 原子落盘）；
    校验用恒定时间比较。加载时拒绝过弱参数（<1 万轮）。
  - 会话：登录（`POST /api/login`）成功签发 32 字节随机令牌，写入
    `fwknop_dash` Cookie（HttpOnly + SameSite=Strict，TLS 下 Secure，12h TTL）；
    `POST /api/logout` 注销并清除 Cookie。
  - 状态查询 `GET /api/auth/state`（公开）：返回 initialized / needs_setup /
    authenticated / write_enabled / version，前端据此切换向导/登录页/主界面。
  - 登录限流：按客户端 IP，5 分钟内失败 5 次锁定 60 秒（HTTP 429）。
  - CSRF：Cookie 会话的写请求必须带 `X-Fwknop-Request: 1` 头（否则 403）；
    Bearer 凭证不经过浏览器，豁免。
  - `DASHBOARD_TOKEN` 保留：作为 Bearer 凭证对全部 /api 有效（无头/CI）；
    登录接口也接受该值作为密码。
- **main.go**：除 4 个鉴权端点与静态页外，全部 /api 经 `requireAuth` 门禁
  （未认证 401，未初始化时带 `needs_setup:true`）；启动时加载认证文件；
  版本号 2.4.0。
- **api.go**：写端点守卫 `requireWrite` 由「可选 Bearer」改为
  「`-enable-write` + CSRF 头」。

### 前端（web/index.html）

- 新增认证门禁界面：加载态 / 初始化向导（设置管理员密码）/ 登录页三卡片，
  按 `/api/auth/state` 与 401 响应自动切换。
- `api()` 统一为非 GET 请求附带 `X-Fwknop-Request: 1`；401 时按
  needs_setup/needs_login 弹回门禁界面；403/429 有明确 toast。
- 侧边栏令牌按钮替换为「注销」；关于页安全说明按新模型重写；版本 v2.4.0。

### 测试（test/run_fork_tests.sh）

- 既有面板探针全部补 Bearer 头；新增 14 个鉴权用例（第二实例、无令牌）：
  未初始化 401、auth/state、短密码/不一致拒绝、初始化+自动登录、重复
  初始化 409、Cookie 访问、缺 CSRF 头 403、带头放行、注销失效、重新登录、
  5 次失败 → 429 锁定。
- 全套回归 **76 通过 / 0 失败**。

## 兼容性说明

- 破坏性变更：未设 `DASHBOARD_TOKEN` 的既有部署重启面板后须先完成初始化
  （或设置 `DASHBOARD_TOKEN` 走 Bearer 通道）。
- 重置密码：删除 `<run-dir>/dashboard_auth.json` 并重启面板即可重新初始化。
