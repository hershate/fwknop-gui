# 03 · 二次开发增强方案

> 完整方案见 [REF/plan/Port Knocking.md](../REF/plan/Port%20Knocking.md)（v2.0）。本文做要点提炼。

## 设计原则（三原则）

1. **单包优先**：保留 fwknop 单包 SPA 的安全优势，动态性只作用于「目的端口」这一路由维度。
2. **向后兼容**：协议升到 `4.0.0`，v3 报文继续可用；新特性按 stanza 开关启用。
3. **最小侵入 / 可降级**：复用 libfko、`incoming_spa`、防火墙后端；新功能以「模块 + 配置开关」加入，关闭即退化为经典 fwknop；任一环节故障保守拒绝 + 告警（不静默放行）。

## 1. TOTP 引擎 + 端口跳变（阶段 1，已完成）

**目标**：SPA 载荷不变，仅目的端口由 TOTP 派生并随时间跳变，实现「无固定监听端口」。

**核心算法**（确定性、双端一致）：
```
range_size = end - start + 1
code_int   = TOTP_HMAC_SHA256(seed, window)     # RFC6238, 截断 8 位
port       = start + (code_int mod range_size)
```

**交付物**（提交 `9a097500`）：

| 文件 | 改动 |
| --- | --- |
| [lib/fko_totp.h](../lib/fko_totp.h) / [lib/fko_totp.c](../lib/fko_totp.c)（新） | RFC 6238（HMAC-SHA256，复用 [lib/hmac.c](../lib/hmac.c)）+ 动态截断 + 大端计数器；API `fko_totp_generate` / `fko_totp_port_now` |
| [common/fko_util.c](../common/fko_util.c) | `fko_totp_to_port`：十进制 TOTP 码 → `[start,end]` 确定性模映射；反转范围返回 0（边界安全） |
| [client/cmd_opts.h](../client/cmd_opts.h) | `--totp-port` / `--totp-seed` / `--port-range` |
| [client/config_init.c](../client/config_init.c) | rc 变量 `USE_TOTP_PORT` / `TOTP_SEED_BASE64` / `PORT_RANGE` 全套 |
| [client/fwknop.c](../client/fwknop.c) | `get_totp_port()`（base64 解码种子→TOTP→端口，用后零填擦除）；发送前注入 TOTP 端口到 `spa_dst_port` |

**设计要点**：时间参数为 `time_t`；零侵入（关 `--totp-port` 即经典 fwknop）；种子用后擦除。默认端口范围 `[30000,60000]`（避开临时端口段），步长 30s，默认 8 位。

## 2. SPA v4 device_id 字段（阶段 3，已完成）

**目标**：每包绑定设备指纹，服务端可做白名单匹配，实现「敲门即身份认证」。

**协议升级**：`FKO_PROTOCOL_VERSION` → `"4.0.0"`（[lib/fko.h:56](../lib/fko.h#L56)）。v4 在 `client_timeout` 之后新增可选末字段 `device_id`（base64）：

```
rand:b64(user):ts:4.0.0:type:b64(message)[:b64(nat)][:b64(auth)][:timeout][:b64(device_id)]
```

**交付物**（提交 `d734a35b` lib + `05d11c67` client）：

| [lib/fko_context.h](../lib/fko_context.h) | `struct fko_context` 增 `char *device_id` |

## 3. CLI 易用性（阶段 5，已完成）

**范围**（经用户确认）：设备指纹 + `fwknop setup` + `fwknop knock` + `fwknop lint`。

**交付物**（提交 `31a5c958` + 可移植性 `98feade3`）：

| 文件 | 改动 |
| --- | --- |
| [lib/fko_fingerprint.c](../lib/fko_fingerprint.c)（新） | **公开** `fko_gen_device_fingerprint()`（[lib/fko.h:605](../lib/fko.h#L605)）：Win 取 hostname‖MachineGuid‖系统盘卷序列号，Unix 取 hostname‖`/etc/machine-id` → SHA256 前 16 字节 → base64 |
| [client/wizard.c](../client/wizard.c) / [.h](../client/wizard.h)（新） | `fwknop setup` 向导：问答 → `fko_key_gen` + TOTP 种子 + 指纹 → 输出 fwknoprc stanza + access.conf stanza + `otpauth://`(base32) |
| [client/cli_subcmds.c](../client/cli_subcmds.c) / [.h](../client/cli_subcmds.h)（新） | 派发：`setup`→向导；`lint [rc]`→校验 stanza；`knock [profile]`→argv 重写 `-n <profile> -R` 复用发送管线 |
| [client/fwknop.c](../client/fwknop.c) | `main()` 在 `config_init` 前注入派发 |

**设计要点**：零侵入派发（仅 `argv[1]∈{setup,lint,knock}` 拦截）；knock 即 `-n -R` 别名；otpauth base32 与服务端 TOTP 一致（digits=8, SHA256, 30s）；指纹只输出哈希不上链明文硬件属性；lint 只读。

### 可移植性修复（`98feade3`，Linux 必需）

阶段 5 初版把指纹放 `client/fingerprint.c`（调内部 `sha256`）、向导调内部 `get_random_data`。但 libfko 仅导出 `^fko_` 符号，客户端链接 `libfko.so` 时这些符号被隐藏 → Linux 上 undefined reference。
**修复**：指纹移入 lib 为公开 `fko_gen_device_fingerprint`；TOTP 种子改用公开 `fko_key_gen`+`fko_base64_decode`；客户端从此**仅用导出 `fko_*`**；并补齐 `Makefile.am` 把阶段 1/3/5 新文件纳入 autotools 编译。

## 4. 客户端↔服务端协议契约（阶段 4 服务端实现依据）

客户端（已实现）发出的 v4 包含：`device_id=<指纹b64>`、目的端口 = `fko_totp_port_now(seed, time, digits, start, end)`。
服务端（阶段 4 待办）须：
1. 解密后 `fko_get_device_id(ctx, &dev)` 取出 device_id，与 access.conf 的 `FINGERPRINT` 白名单做**常量时间比较**（复用 `common/fko_util.c` 的 `constant_runtime_cmp`）。
2. 可选 `REQUIRE_TOTP_PORT_MATCH`：用 stanza 的 TOTP 种子+端口范围重算当前应到端口，与包**实际到达的 dst 端口**比对（NFQ 可获原始 dst）。这样端口本身就是一次性口令——即便加密包被重放到别的端口也会被拒。
3. 指纹不符 / 端口不匹配 / 过期 → 静默丢弃 + 结构化审计。

## 6. 服务端管理易用性（2026-08-13 决策确认）

> 完整设计见 [REF/plan/Port Knocking.md §7.6](../REF/plan/Port%20Knocking.md)（v2.1）与附录 E。

**三项决策**（用户确认）：① **CLI 先行**（`fwknopd-admin` 承载全部管理逻辑），WebUI/TUI 后置为壳；② 凭证文件**支持明文+加密、默认加密**（scrypt + AES-256-GCM）；③ **默认启用 TOFU** 首次使用设备绑定。

**要点**：

- **界面分层**：`fwknopd-admin` CLI（C，`server/`，复用 libfko 密钥生成）→ TUI 壳（dialog/whiptail）与 WebUI 壳（Go/Python，默认只读+localhost+写操作额外认证）后置（阶段 5+）。
- **授权 QR**：`fwknopd-admin user add --qr` 生成 `fwknop://<server>?user&key&hmac&totp&range&access&name` URI 的终端 ANSI QR（qrencode，可选依赖）；客户端 `fwknop import <qr.png|uri|file>` 自动生成 rc stanza。与 `otpauth://`（供 Authenticator 验证器）严格区分。
- **凭证文件**：JSON v1（`fmt: fwknop-credential`，含 Rijndael/HMAC/TOTP 全套 b64 密钥 + 端口范围 + 过期时间），默认 passphrase 加密；**凭证即邀请函**，撤销 = `user rm` 立即断权。
- **TOFU 绑定**：stanza 指纹白名单留空 + `REQUIRE_FINGERPRINT Y` 时，首个通过密钥+HMAC+新鲜度校验的 v4 包 device_id 自动锁定（`FINGERPRINT_TOFU_TIMEOUT` 宽限期，默认 86400s）+ 审计「新设备绑定」。凭证泄露后在其他设备无效；诚实局限是首用抢占风险，靠短宽限窗口 + `to-fingerprint` 人工复核兜底。
- **安全纪律**：QR/凭证是持票凭证（bearer credential）——一次性展示、不落日志、导出即标记、可撤销。
- **上游雏形**：[extras/console-qr/console-qr.sh](../extras/console-qr/console-qr.sh)（仅明文 SOURCE+KEY → QR），本方案为带 HMAC/TOTP/指纹与安全模型的完整升级。
