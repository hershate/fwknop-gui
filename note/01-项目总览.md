# 01 · 项目总览

## 1. fwknop 是什么

fwknop（**F**ire**W**all **Kn**ock **Op**erator）实现 **单包授权（Single Packet Authorization, SPA）**：
用一个**加密、防重放、经 HMAC 认证**的单个数据包，向默认 DROP 的防火墙申请临时开放某服务端口。

典型场景：把 SSH 藏在默认拒绝的防火墙后面，扫描器（Nmap/Masscan）看不到任何开放端口；
只有持有密钥的客户端发一个 SPA 包，fwknopd 才临时放行——过期自动关闭。

详见上游 [README.md](../README.md) 与 [doc/fwknop.man.asciidoc](../doc/fwknop.man.asciidoc)。

## 2. SPA vs 传统端口敲门（Port Knocking）

| 维度 | 端口敲门 PK | 单包授权 SPA（fwknop） |
| --- | --- | --- |
| 包数 | 多包序列 | **单包** |
| 加密/认证 | 通常无 / 弱 | Rijndael 或 GnuPG + HMAC（encrypt-then-MAC） |
| 防重放 | 难 | timestamp + SHA-256 摘要重放缓存 |
| 抗伪造/DoS | 弱（插入一个伪造包即破坏序列） | 强（认证失败静默丢弃） |
| 可扫描性 | 序列可被嗅探 | 加密载荷，扫描器只见 DROP |

SPA 在安全性上**严格优于**多包敲门，这也是本 fork 选择「扩展现有单包 SPA」而非另建多包敲门子系统的根本理由（见 [REF/plan/Port Knocking.md §0.2](../REF/plan/Port%20Knocking.md)）。

## 3. fwknop 已具备 vs 本 fork 净新增

| 需求 | 上游 fwknop 现状 | 本 fork 处置 |
| --- | --- | --- |
| 加密 + HMAC 认证 | `lib/fko_encryption.c` + `lib/fko_hmac.c` | 已具备，直接复用 |
| timestamp 防重放 | `timestamp` + `check_pkt_age` + `replay_cache` | 已具备，仅收紧配置 |
| 最小权限/时效端口 | `OPEN_PORTS` + `FW_ACCESS_TIMEOUT` + iptables `_exp_` 注释 | 已具备 |
| **一次一密的动态端口** | 固定 62201 | **净新增：TOTP→端口跳变** |
| **用户/设备身份绑定** | 仅 `username` | **净新增：v4 `device_id` 字段 + 指纹白名单** |
| **多因素 TOTP** | 无 | **净新增：TOTP 引擎（共享模块）** |
| 透明自动敲门 / GUI / 运维面板 | 仅手动 CLI | 净新增（大部分待办） |

## 4. 本 fork 的二次开发目标

1. **无固定监听端口**：TOTP 驱动目的端口随时间跳变，扫描器看不到稳定端口。
2. **强身份绑定**：每包绑定设备指纹 + TOTP，敲门即身份认证。
3. **零信任最小权限**：身份→策略→时效端口，全程可审计。
4. **用户无感**：透明自动敲门，CLI/GUI 双形态，运维可视化。
5. **向后兼容**：与现有 fwknop v3 客户端/服务端共存，可分阶段灰度。

来源：[REF/plan/Port Knocking.md §1.3](../REF/plan/Port%20Knocking.md)。

## 5. 版本与许可

- **客户端版本**：`2.6.11`（[VERSION](../VERSION)），沿用上游版本号；本 fork 未另立发行版本号。
- **SPA 协议版本**：`4.0.0`（本 fork 升级；上游为 `3.0.0`）。
- **许可证**：GPL v2 or later（[COPYING](../COPYING)）。
- **构建**：GNU autotools（[autogen.sh](../autogen.sh)、[configure.ac](../configure.ac)）；Windows 原生构建见 [win32/](../win32/)。

## 6. 平台支持现状

- **客户端（fwknop）**：Linux / macOS / *BSD / Windows（Cygwin 或 win32 原生 MSVC）；本 fork 在 Windows MinGW GCC 15.2.0 完成阶段 1/3/5 的编译与单元验证。
- **服务端（fwknopd）**：仅 Unix（依赖 iptables/firewalld/PF/ipfw、libpcap/NFQ）；阶段 2/4 的服务端工作需在 Linux 上进行。
